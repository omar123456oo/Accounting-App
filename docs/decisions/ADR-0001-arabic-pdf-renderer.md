# ADR-0001: Arabic PDF renderer

**Status:** Proposed. The default below stands until a native Arabic reader has reviewed the two sample PDFs (see "Review still required").

## Context

Invoices, statements, tax forms and payslips must print correct Arabic: joined letters, right-to-left flow, mixed Arabic and Latin text, Arabic-Indic and Western digits, EGP amounts and right-to-left tables. A wrong rendering on a tax invoice is a business defect, so the engine is chosen on rendering quality, not convenience.

## Options

| | mPDF | Headless Chromium (Spatie Browsershot) |
|---|---|---|
| Text shaping | Own engine; supports Arabic with bundled fonts, but is a re-implementation of the web's rules | The browser's own shaping and bidi, same as the Angular screens |
| CSS support | Partial (no flexbox/grid, limited modern CSS) | Full |
| Runtime weight | Pure PHP | Chromium + Node/Puppeteer in the container |
| Speed | Fast | Slower per document (browser start) |

## Decision

Use **headless Chromium** behind the `PdfRenderer` interface (`app/Modules/Platform/Pdf`). `MpdfPdfRenderer` stays in the repository only for the comparison and can be removed once this ADR is accepted.

## Rationale

The plan says to default to Chromium if mPDF shows any defect, and Chromium is the engine most likely to match what users already see on screen. Because every caller depends on `PdfRenderer`, switching later is a one-line binding change in `AppServiceProvider`.

## Consequences

- The PHP image carries Chromium, Node and a font with Arabic coverage (`fonts-noto-core`).
- Rendering runs as root in a container, so Chromium is started with `--no-sandbox`. Render only HTML the application built itself; never render user-supplied HTML or URLs.
- Documents should be generated by the queue worker, not inside a web request, once volumes grow.

## Review still required

1. `docker compose exec app php artisan pdf:spike both`
2. Open `backend/storage/app/spike/sample-mpdf.pdf` and `sample-chromium.pdf` side by side.
3. Check: letter joining, digit order in `١٢٣٤٥٦٧٨٩` and `123456789`, the `EGP 3,001.00` amount inside Arabic text, table column order (first column at the right) and the header row.
4. Record the result here and change the status to Accepted, or switch the binding to mPDF if Chromium shows a defect.
